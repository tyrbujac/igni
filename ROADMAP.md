Real-world JSON is heavily nested; `{user with profile: {user.profile with settings: {user.profile.settings with dark_mode: true}}}` is exhausting. Two proposed shapes from the panel: deep-with sugar (recursive `with`-chain elision) OR `update_path(object, "profile.settings.dark_mode", true)` builtin. Coupled stylistic question with the existing `{base with ...}` rule.
- **Lifecycle hook (`once:` / `on appear:`) — 2/7 v0.17.0 meta-review** (gemini-3-flash spec + gpt c'sheet, cross-model). For analytics events fired once on screen open, socket-connection setup, "fire-once-on-mount" patterns. Risk: bringing back `useEffect` complexity. Promotion candidate paired with the `every` family — same scoping rules; just a one-shot variant. Already on Ideas list (see "Lifecycle hooks (`on appear`, `on disappear`)") — meta-review reinforces.
- **Async cancellation semantics — 1/7 v0.17.0 meta-review** (gpt c'sheet alone). Currently undefined — when `query` is reassigned mid-fetch (`query = "a" / "ab" / "abc"`), do old fetches cancel? Race conditions? Production apps with reactive search will hit this. Needs a design note before any cancellation primitive lands; meanwhile a docs note acknowledging the current undefined behaviour would help.
- **Internationalisation primitives — 1/7 v0.17.0 meta-review** (opus spec alone, score 0/10). String wrapping (`t("hello")`), plural rules, locale-aware date/number formatting, RTL handling. Single-cell raise but coupled with a11y/animation as the "v1.0 cannot ship without primitive support for X" trio. Tracked here so the trio is visible together; promotion priority below a11y/animation given lower convergence.
- **Component event canvas vocabulary — Igni Studio Tier C** (logged 2026-04-28; gpt-5.5 1/3 Q1 in `tests/igni-studio-strategy/`). The `emit X v` + parent's `on X(name):` payload binding has no canvas representation — visual editing of component event contracts requires API-inspector tooling, not just visual layout. Open question for post-v1.0 Studio canvas design; tracked here so the gap doesn't get re-discovered. Folded into `docs/private/115_igni_studio_strategy.md` Tier C.
- **Cursor + Figma-frame-import competitor canary — Igni Studio Tier C** (logged 2026-04-28; opus 1/3 Q5 in `tests/igni-studio-strategy/`). If Cursor ships a "Figma export → Igni source" feature, Studio's canvas becomes redundant for the import-once-then-edit-source workflow (the workflow most teams will adopt by default). Worth tracking publicly. Not a spec change; a competitive-watch entry that affects the strategic baseline in `docs/private/115`.
