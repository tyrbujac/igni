**1 — Hold.** Bundling animation, snapshot, and time-mocking is the correct architectural choice and crucial for a stable v1.0. Shipping animation without snapshot testing violates the principle that all UI logic must be verifiable; an `expect seen "Welcome"` assertion after a conditional swap only proves the final state, leaving the intermediate transition entirely untested and susceptible to regression. Conversely, snapshot testing without time-mocking is inherently flaky due to `now()` and async-derived content. Splitting animation to v0.19 and snapshots to v0.20 would result in a cycle where you are shipping un-verifiable motion features. The text-tree snapshot approach is cheap enough to implement alongside animation, avoiding the risk of divergent semantics that would occur if time-mocking were built iteratively across two releases.

**2 — Hold.** The declarative `spring(value)` lock survives the Flutter-runtime fit and is vastly superior for zero-shot LLM accuracy. In a duration model (`transition: 200ms`), an LLM must correctly attach the modifier to the layout node, creating a structural disconnect between the animating data state and the visual tree. With `dropdown_height = spring(items.length * row_height)`, the animation is intrinsically bound to the data via lexical reactivity—when `items.length` reassigns, the spring updates its target and inherently drives Flutter’s `TweenAnimationBuilder` (using a `SpringSimulation` curve). This abstracts away the heavy boilerplate of Flutter’s `AnimationController` lifecycles entirely. Furthermore, for reduced-motion accessibility, `spring()` provides a centralized compile-target hook to instantly snap to the target value across the entire app, whereas scattered explicit durations would require complex AST transforms to strip out.

**3 — Refine.** The boundary is conceptually clean but practically leaks around non-numeric value transitions. If an LLM or user wants to crossfade a text label when a string variable changes (e.g., `status = "Loaded"`), `spring("Loaded")` makes no sense, and the current `transition:` boundary cannot apply to raw value reassignment without forcing unnatural workaround patterns like `if status == "Loaded": label status else: label old_status`. This fights the "one way" rule by demanding structural gymnastics for a simple visual fade. The smallest patch is to widen `transition: <token>` to apply directly to standard components displaying state (e.g., `label status, transition: fade`), which easily compiles down to a Flutter `AnimatedSwitcher` keyed on the variable's value, closing the gap without adding new primitives or breaking the token-only constraint.

**4 — Refine.** There is a severe, Pomodonut-style bug in how `snapshot "name"` interacts with `mock every: advance` and `spring()` (addressing b and c). In standard Flutter testing, the tree is allowed to settle, meaning a snapshot immediately after a tap would capture the *target* value of a spring, completely skipping the intermediate frames. To make the `advance 1000ms` example verifiable, the snapshot primitive must rigorously capture the exact mid-flight frame at the current test-clock time, not the settled state. Furthermore, `freeze_time: <iso-timestamp>` and `mock every: advance` must explicitly compose: `advance` must mutate the test-scoped frozen clock. If `freeze_time` locks `now()` to a static constant that `advance` cannot budge, time-based animations and their assertions will entirely fail to evaluate. (Issues a and d natively resolve: per-row `spring` works via standard tree-identity state retention, and `AnimatedSwitcher` handles sudden third-state interruptions gracefully).

**5 — Hold.** Deferring image/golden-file snapshots to v0.20+ is the correct scoping decision that protects the spec budget. Text-tree snapshots will catch the vast majority of structural regression bugs—conditional render swaps, list reorderings, and text mutations. Crucially, as long as the Igni text-tree serialization includes bound layout properties (e.g., outputting `<layout vertical padding="large" height="100">`), users can still assert on `spring()`-driven layout animations via text diffs without needing pixel-perfect image comparison. Image golden tests introduce massive flakiness regarding font rendering, platform anti-aliasing, and CI environments; keeping them out of v0.19 ensures the core snapshot mechanism stabilizes first. Users will not write complex Flutter-test workarounds because the deterministic text-tree diff provides 90% of the verification value for 10% of the maintenance cost.

**6 — Hold.** The proposed time-control vocabulary (`mock now:`, `freeze_time:`, and `mock every: advance`) is entirely sufficient for v0.19 and strictly adheres to the "optimise for rule simplicity" spec-budget constraint. Introducing a richer vocabulary like `step`, `replay`, or `tz` (timezone) violates the "one way to do everything" rule and preempts empirical pull. Stepping through frames for visual debugging is already achievable by issuing sequential `advance 16ms` calls followed by `snapshot` assertions, while timezone mocking naturally belongs in the v0.21+ internationalization bundle. The v0.18 mock-block patterns are robust enough to carry time-mocking; keeping the surface area minimal optimizes for LLM predictability while fully closing the non-determinism bug surface for snapshot testing.
